Rule codes#

Each code identifies one normative statement in the NGFF specification, and links to the exact text in the spec that states it, for each spec version. yaozarrs errors and warnings for spec violations carry these codes once they are tagged.

  • YZ-<AREA>-<NNN> codes refer to statements in the NGFF spec or its JSON schemas.
  • YZ-<NNN> codes are checks that yaozarrs adds beyond the spec.

Codes are permanent: a code is never renumbered or reused. If a statement changes meaning in a later spec version, its code is retired and a new one supersedes it.

Note

These codes are assigned by yaozarrs; they are not (yet) part of the NGFF specification itself (see ome/ngff#646). If official codes are adopted, each spec rule will record its official code. Spec versions audited so far: 0.4, 0.5, 0.6. Every RFC 2119 keyword in those versions is inside the quote of a rule here, or of an entry (with a reason) in skipped.toml.

Checked in lists the spec versions in which yaozarrs reports a rule's code when a document breaks the rule. If none are listed, yaozarrs may still reject such a document, but not under this code (yet).
