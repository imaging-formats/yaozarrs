Images#

Image #

Top-level OME-NGFF image metadata (ome in an image group's zarr.json).

Contains one or more multiscale pyramids, plus optional OMERO rendering hints.

Typical Structure

my_image/
├── zarr.json          # contains ["ome"]["multiscales"]
├── 0/                 # Highest resolution array
├── 1/                 # Next resolution level
└── labels/            # Optional segmentation masks
    ├── zarr.json      # contains ["ome"]["labels"]
    └── 0              # Multiscale, labeled image.

Note

For the optional labels group, see LabelsGroup.

Multiscale #

A multi-resolution image pyramid, with its coordinate systems.

All datasets (resolution levels) map into the same "intrinsic" coordinate system, which represents the image in its native physical coordinates. Additional coordinateTransformations may link the intrinsic coordinate system to other coordinate systems of this multiscale, or to those of its label images.

def validate_multiscale_axes(axes: Sequence[Axis]) -> None:
    """Rules for the axes of coordinate systems inside `multiscales` metadata.

    Raises
    ------
    ValueError
        If the axes violate any of the rules.
    """
    # NOTE: the prose says these rules "apply to all coordinate systems inside
    # multiscales metadata", including "`axes` MUST contain 2 or 3 entries of
    # `type:space`".  But axes.schema allows either 2-3 "space" axes or >= 2 "array"
    # axes, so we accept the latter with a warning.
    # (only the space-axis rule is relaxed for those; the other rules still apply)
    n_space = sum(ax.type == "space" for ax in axes)
    array_cs = sum(ax.type == "array" for ax in axes) >= 2 and not 2 <= n_space <= 3
    if array_cs:
        warnings.warn(
            "Coordinate systems inside multiscales MUST contain 2 or 3 axes of type "
            "'space' according to the spec prose; coordinate systems made of 'array' "
            "axes are only allowed by the JSON schema.",
            ValidationWarning,
            stacklevel=2,
        )

    # The length of `axes` must be between 2 and 5
    if not 2 <= len(axes) <= 5:
        raise ValueError(f"There must be between 2 and 5 axes. Found {len(axes)}.")

    # `axes` MUST contain 2 or 3 entries of `type:space`
    if not array_cs and not 2 <= n_space <= 3:
        raise ValueError("There must be 2 or 3 axes of type 'space'.")
    # `axes` MAY contain one additional entry of `type:time`
    if sum(ax.type == "time" for ax in axes) > 1:
        raise ValueError("There can be at most 1 axis of type 'time'.")
    # `axes` MAY contain one additional entry of `type:channel` or a null / custom type.
    # NOTE: this sentence is unchanged from v0.5; like v05 we only limit `channel` axes
    # to one, and allow several custom/untyped axes (within the 5-axis limit).
    if sum(ax.type == "channel" for ax in axes) > 1:
        raise ValueError("There can be at most 1 axis of type 'channel'.")

    # `axes` entries MUST be ordered by `type` where the `time` axis must come first
    # (if present), followed by the `channel` or custom axis (if present) and the
    # axes of type `space`.
    type_order = {"time": 0, "space": 2}
    order = [type_order.get(ax.type or "", 1) for ax in axes]
    if order != sorted(order):
        raise ValueError(
            "Axes are not in the required order by type. "
            "Order must be [time,] [channel or custom,] space."
        )

def check_transform_ndim(t: CoordinateTransformation, n_in: int, n_out: int) -> None:
    """Check that the parameters of `t` fit `n_in` input and `n_out` output axes.

    Raises
    ------
    ValueError
        If they don't.
    """

    # The parameter values ... MUST be compatible with input and output space
    # dimensionality
    def _fail(msg: str) -> NoReturn:
        raise ValueError(f"{t.type}: {msg} (input has {n_in}, output has {n_out} axes)")

    if isinstance(t, (TranslationTransformation, ScaleTransformation)):
        # Input and output dimensionality MUST be identical and MUST equal the
        # length of the `scale`/`translation` array (N).
        params = t.translation if isinstance(t, TranslationTransformation) else t.scale
        if not len(params) == n_in == n_out:
            _fail(f"has {len(params)} values")
    elif isinstance(t, (IdentityTransformation, DisplacementsTransformation)):
        # (`displacements` require M=N)
        if n_in != n_out:
            _fail("input and output must have the same number of axes")
    elif isinstance(t, MapAxisTransformation):
        # The length of the array MUST equal the number of dimensions in both the
        # input and output coordinate systems. Each integer in the array MUST be a
        # valid zero-based index into the input coordinate system's axes
        # (that it's a permutation of 0..N-1 is checked by MapAxisTransformation)
        if not len(t.mapAxis) == n_in == n_out:
            _fail(f"has {len(t.mapAxis)} indices")
    elif isinstance(t, ProjectAxisTransformation):
        dropped, created = t.droppedInputs or [], t.createdOutputs or []
        if any(i >= n_in for i in dropped):
            _fail(f"droppedInputs {dropped} out of range")
        if any(i >= n_out for i in created):
            _fail(f"createdOutputs {created} out of range")
        if n_out != n_in - len(dropped) + len(created):
            _fail(f"drops {len(dropped)} and creates {len(created)} axes")
    elif isinstance(t, AffineTransformation):
        # the outer array MUST be length `M` and the inner arrays MUST be length N+1
        if t.affine is not None:
            m, n1 = len(t.affine), len(t.affine[0])
            if m != n_out or n1 != n_in + 1:
                _fail(f"matrix is {m}x{n1}, expected {n_out}x{n_in + 1}")
    elif isinstance(t, RotationTransformation):
        # Input and output dimensionality (N) MUST be identical.
        if n_in != n_out:
            _fail("input and output must have the same number of axes")
        if t.rotation is not None and len(t.rotation) != n_in:
            _fail(f"matrix is {len(t.rotation)}x{len(t.rotation)}")
    elif isinstance(t, BijectionTransformation):
        # Its input and output spaces MUST have equal dimension. The input and
        # output dimensions for the both the forward and inverse transformations
        # MUST match bijection's input and output space dimensions.
        if n_in != n_out:
            _fail("input and output must have the same number of axes")
        _check_child(t, "forward", t.forward, n_in, n_out)
        _check_child(t, "inverse", t.inverse, n_out, n_in)
    elif isinstance(t, SequenceTransformation):
        # (intermediate dimensionality is inferred from each step's parameters. Where
        # it can't be (e.g. after a `coordinates` step), checking resumes at the next
        # step whose parameters fix its own input size. The last step must produce
        # the sequence's output.)
        n: int | None = n_in
        steps = t.transformations
        for i, step in enumerate(steps):
            if n is None:
                n = _own_ndim(step)[0]
            n_next = n_out if i == len(steps) - 1 else _output_ndim(step, n)
            if n is not None and n_next is not None:
                _check_child(t, f"transformations[{i}]", step, n, n_next)
            n = n_next
    elif isinstance(t, ByDimensionTransformation):
        # The integer values in these arrays correspond to the axis indices in the
        # `byDimension`'s ... `input` and `output` coordinate systems
        for i, item in enumerate(t.transformations):
            if any(ax >= n_in for ax in item.inputAxes):
                _fail(f"transformations[{i}].inputAxes {item.inputAxes} out of range")
            if any(ax >= n_out for ax in item.outputAxes):
                _fail(f"transformations[{i}].outputAxes {item.outputAxes} out of range")
        # Every axis index in the parent byDimension's `output` coordinate system
        # MUST appear in exactly one child transformation's `outputAxes` array.
        covered = {ax for item in t.transformations for ax in item.outputAxes}
        if missing := sorted(set(range(n_out)) - covered):
            _fail(f"output axes {missing} are not covered by any transformation")

Labels#

LabelImage #

A complete label image with multiscale pyramids and label metadata.

Combines the standard image structure (multiscale pyramids, coordinate systems, etc.) with label-specific metadata (colors, properties, source reference). Label images must use integer data types.

Relationship to Image

This is an Image with additional image-label metadata. The multiscale pyramids follow the same structure as regular images but contain integer segmentation masks instead of intensity data.

Parameters:

Name Type Description Default
image_label ImageLabel

Label-specific metadata (colors, properties, source link)

 required

ImageLabel #

Metadata for a segmentation/annotation label image.

Enhances a multiscale label image with display colors, semantic properties, and links back to the source intensity image. Label images are integer-valued arrays where each unique value represents a distinct object or region.

Plate #

Top-level plate metadata for high-content screening.

This model corresponds to the ome metadata in a plate group's zarr.json, organizing a microplate's wells in a grid layout. Each well contains one or more fields-of-view, which in turn contain multiscale images.

Typical Structure

my_plate.ome.zarr
├── A                       # Row A
│   ├── 1                   # Column 1
│   │   ├── 0               # FOV 0 (in A1)
│   │   │   ├── s0          # FOV 0 - Multiscale level 0
│   │   │   └── zarr.json   # contains ["ome"]["multiscales"]
│   │   ├── 1               # FOV 1 (in A1)
│   │   │   └── ...
│   │   └── zarr.json       # well metadata (contains ['ome']['well'])
│   └── 2
│       └── ...
├── B
│   └── ...
└── zarr.json                # plate metadata (contains ['ome']['plate'])

Collections#

Bf2Raw #

Model for zarr.json in a group representing multi-series image collections.

The bioformats2raw layout is a transitional specification for filesets that already exist in the wild. An upcoming NGFF specification will replace this layout with explicit metadata. It is currently the only way to represent multi-position image collections, and it has a recommended place for OME-XML metadata.

Typical Structure

root.ome.zarr             # One converted fileset from bioformats2raw
├── zarr.json             # Contains "bioformats2raw.layout" metadata
├── OME                   # Special group for containing OME metadata
│   ├── zarr.json         # Contains "series" metadata
│   └── METADATA.ome.xml  # OME-XML file stored within the Zarr fileset
├── 0                     # First image in the collection
├── 1                     # Second image in the collection
└── ...

Note

The OME/zarr.json file typically contains Series metadata that explicitly lists image paths. If not present, images MUST be numbered as shown above, starting from 0, e.g., 0/, 1/, 2/, etc.

Name Type Description Default
version Literal['0.6', '0.6rc0', '0.6.dev4']

OME-NGFF version

 '0.6'

Layout version marker added by bioformats2raw (currently 3)

 3

Series #

Model for OME/zarr.json in a Bf2Raw collection.

Used when converting files containing multiple distinct images (e.g., multi-series microscopy formats) to OME-NGFF. Each series becomes a separate image group, and this metadata lists them all.

Note

The spec is ambiguous about whether series is required. This library treats it as required for disambiguation, since otherwise this model would simply contain "version".
